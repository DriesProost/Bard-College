# Phase 2 validation — Conservatory foundations

21 October 2026 · application 1.2.0. Phase 2 implements only the approved Music lessons 01–09. Phase 3 and the seven shared studios have not been started. Full Windows acceptance is scheduled after this phase, as requested.

## Implemented boundary

- All 38 Writing lesson objects, their versions and all 30 original IDs are unchanged against the exact Phase 1 baseline. Existing writing projects, snapshots, attempts, feedback, settings, credentials and participation remain supported. Independent Music navigation, progression and criterion evidence use the Phase 1 architecture; no lyrical completion becomes Music mastery.
- Nine Music units follow `MUSIC_CURRICULUM.md`: musical intention; pulse/silence; durations; 3/4 versus 4/4; 6/8 versus 3/4; pitch locations/unisons/octaves; steps/leaps; a major collection as a palette; a two-bar miniature. Objectives, readiness links and assessment principles are retained. Each has an achievable five-minute minimum, original comparison, optional longer work, retrieval links and an unfamiliar challenge.
- Keyboard-editable six-string timed tablature, standard tuning/no capo, sounding pitch labels, counted rhythms/rests/holds, two alternative phrases and up to two bars per phrase. Arrow keys navigate, digits enter frets, a numeric field supports frets 10–24, and Delete makes a rest. Accessible text describes every slot. Notes are monophonic and cannot cross a bar line. Metre changes request confirmation before clearing a phrase.
- Original playable demonstrations are curriculum data, validated by the same schema as student work. Web Audio produces synthetic note/pulse playback. In 6/8 the compound pulse is explicitly distinguished from quarter-note tempo and the 3/4 grouping. Optional original C/Am chord-reference diagrams include complete textual string/fret descriptions. Staff engraving is not included; no staff reading is required.
- Local microphone capture/playback, saved lesson/sketch links, restart persistence and deletion. Up to two minutes / 12 MiB per take, 200 takes / 256 MiB per profile. Audio-only permission requires a trusted main-frame request after a recording action; camera and unrelated permission requests are denied. Missing/denied/busy input, empty capture, capture errors, save failure and playback failure have messages. Failed saves retain the take in memory for retry/discard; normal closing waits for capture/save. An abrupt crash or power loss can still lose an unfinished take.
- Music attempts, revisions and evidence use the existing SQLite history without a new database schema migration. A pristine Phase 1 curriculum is backed up before adding the nine lessons. Custom content remains unchanged until its previewed merge. Recording audio and UUID manifests live in the profile's `recordings/` directory. Whole-profile backups must include that directory; database-only recovery copies do not contain audio.
- GPT-6 Luna is the exclusive model. Musical feedback receives an accessible counted document and explicitly labelled student listening observations. It receives no recording bytes, recording filenames, paths or recording UUIDs. The tutor is instructed that it has heard no audio, cannot assess performance from text, must preserve intent and must treat artistic judgments contextually. Feedback is optional; local work has no API dependency.
- Completion records participation. Criterion evidence is an explicit self-report attached to a draft/version, not a certified skill score. Retained Music evidence requires independent work followed by the unfamiliar challenge and changed musical content; changing only the sketch ID, name or listening note is insufficient. Neither app completion nor AI feedback establishes educational effectiveness.

## Windows PC acceptance still required

Use `release/Bards-College-Setup-1.2.0-x64.exe` on Windows 10/11 x64, under a normal user account. It is unsigned. The installer bundles Electron/Chromium and the application; Node, VS Code and a Vite server are not required. Perform the checks below on a copy of the existing profile first, preserving the whole closed profile as a recovery copy.

1. Upgrade the existing installation, launch from its shortcut with terminals/VS Code closed, and verify existing Writing projects, snapshots, progress, preferences and saved credential. Check that Writing still has 38 lessons and Music has nine; earlier lyrical lessons must not grant Music evidence.
2. Disconnect the network. Open Music 01, set an intention, enter two short gestures with mouse and keyboard, play both examples, save, revise and restart. Try 3/4, 4/4, 6/8, explicit rests/holds and a two-bar miniature. Complete a minimum exercise and independently inspect the skill criteria. Repeat a Writing save/revise/export journey.
3. With an actual microphone/interface and guitar, grant desktop-app microphone access in Windows privacy settings. Record, stop/save, listen and restart; replay the take, then delete one. Close during a take and verify it was saved. Check microphone release after stopping/navigation/closing, the selected Windows default input device, hardware levels, clipping and playback latency.
4. Deny microphone permission, unplug/disable the device, or make it unavailable. Confirm the message is helpful and the written sketch remains safe. Re-enable permission/device and retry. Check storage-full/write-denied recovery on a disposable profile. Use headphones to prevent feedback.
5. Confirm the real key is protected by Windows DPAPI, remains usable after restart under the same Windows account, and can be removed. Run **Test AI Connection** using an account with actual `gpt-6-luna` access. A live account/model/latency/billing check was not possible here; no fallback model exists. Request musical feedback and confirm it discusses the document, not an allegedly heard take.
6. Check keyboard focus, screen-reader names/counts, Windows display scaling, output volume and low/no-audio-device behavior. Have a guitarist/educator and a beginner try the nine minimum tasks, their timing and unfamiliar transfer tasks; code tests do not establish those learning outcomes.
7. Verify install/update/uninstall shortcuts and preservation of the entire profile, including recordings. Close the app before backing up. Never overwrite an open SQLite database or copy its main file while ignoring WAL/SHM state. Avoid downgrading against a live profile; restore a separate whole-profile recovery copy if rollback is necessary.

No AI audio analysis, audio upload, automatic transcription, later Music lessons or shared studios have been added.
